# تقرير المشروع

## نظرة عامة

سطح مكتب Ubuntu 24.04 كامل يعمل داخل حاوية ويُعرض في المتصفح عبر KasmVNC.
الواجهة خفيفة: XFCE بلا مؤثرات ولا أيقونات على الخلفية، وصفحة تحكم صغيرة
بلا أي إضافات.

## المكوّنات

| المكوّن | الدور |
|---|---|
| Ubuntu 24.04 | نظام الأساس |
| XFCE 4 | جلسة سطح المكتب |
| KasmVNC 1.5.0 | خادم HTTP/WebSocket مع ترميز متكيّف |
| Google Chrome | المتصفح الافتراضي |
| supervisord | PID 1 داخل الحاوية |
| `control-server.py` | المنفذ العام: صفحة الحالة + reverse proxy |
| طبقة توافق systemd | `systemctl`/`journalctl` فوق Supervisor |

## ما تمت إزالته

- **Tailscale**: الحزمة، الخدمة، سكربتاتها، وحداتها، وكل واجهتها في صفحة
  التحكم. لم يبق أي أثر.
- **Hermes / DeepSeek**: التثبيت، سكربت الإقلاع، برنامج Supervisor،
  والمتغيّر `DEEPSEEK_API_KEY`. لم يبق أي أثر.
- **OpenClaw**: أُزيل سابقاً لتوفير الذاكرة ووحدة المعالجة.

## تدفّق الطلب

```
المتصفح → :3000 (control-server) → 127.0.0.1:6080 (Xvnc) → X11 :1 → XFCE
```

`/` سطح المكتب عند `PUBLIC_DESKTOP=1`، و`/status` صفحة الحالة،
و`/api/status` بيانات JSON، و`/healthz` فحص الصحة.

## systemd

داخل الحاوية لا توجد systemd حقيقية: supervisord هو PID 1، والطبقة في
`systemd/` تحاكي واجهة الأوامر فقط. هي ليست حداً أمنياً ولا تدير cgroups.

**systemd الحقيقية** متوفرة عبر مسار VPS الأصلي:

```
vps/install.sh          # تثبيت على Ubuntu 24.04 نظيف
vps/systemd/*.service   # وحدات systemd فعلية
```

راجع `docs/DEPLOY-VPS.md`.

## القيود

- لا GPU: رسم برمجي (llvmpipe).
- الملفات تضيع عند إعادة نشر الحاوية.
- لا صوت.
- الطبقة المتوافقة لا تدعم cgroups أو المؤقتات.

## الأمان

- `VNC_PW` إلزامية وقوية، ولا تُخزَّن في الصورة.
- KasmVNC يستمع على loopback فقط؛ المنفذ العام الوحيد هو 3000.
- عند `PUBLIC_DESKTOP=1` يكون الرابط العام محمياً بـ HTTPS + Basic Auth.
